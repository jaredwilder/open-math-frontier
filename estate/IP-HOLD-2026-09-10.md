# IP Hold Boundary for the Open Math Drop

**Author:** Jared Wilder  
**Date:** 2026-09-10

The default rule for this release is **publish the mathematics**.

The following categories are deliberately excluded from automatic publication because the estate itself identifies them as potentially load-bearing technical or applied IP. This is a disclosure boundary, not a claim that any listed concept is patentable.

## Hold categories

- concrete authenticated robust-reasoning capsule implementations;
- carry-free heterogeneous distributed aggregation packet / decoder implementations;
- proof-carrying action-authorization mechanisms tied to executable systems;
- verified rebasable behavior-catalog implementations;
- unreleased claim charts, invention disclosures, patent-family drafting material, and implementation diagrams;
- patient-specific biomedical monitoring / intervention embodiments and clinical product mechanisms;
- digital-twin pharmacology implementation details whose value depends on the applied system rather than a standalone mathematical theorem;
- organ-network / instability / intervention product embodiments where the mathematical operator is embedded in a patent-facing clinical mechanism;
- commercial battery, cryptographic, HSM, compliance, or industrial implementations whose novelty depends on system integration;
- private commercial repositories merely because they happen to contain mathematics.

## Not automatically held

The estate's own theorem / patent docket explicitly treats the following as mathematics rather than the invention center:

- mathematical obstruction classifications;
- abstract Search/Court distinctions;
- standard monoid / automata mathematics;
- B_h / shifted sparse-encoding theorems by themselves;
- graph, CSP, number-theory, combinatorics, geometry and formal-proof results whose value does not depend on a secret technical embodiment;
- counterexamples, exact finite certificates and negative theorems;
- public-source formalizations and theorem audits.

Those can be released with appropriate scope and novelty language.

## The practical test

Before an estate object is made public, ask:

1. Can the mathematical claim stand alone as mathematics?
2. Does publication reveal a particular technical packet layout, controller, decoder, patient workflow, product architecture, claim element, or unreleased implementation that is itself the commercial center?
3. Is the object already inside a filed / public patent family or otherwise cleared for disclosure?
4. Can a scope-clean theorem statement be separated from the implementation?

If (1) is yes and (2) is no, publish by default.

If (2) is yes and filing/clearance is uncertain, hold the implementation and publish only the separable mathematics.

## Why this exists

"Release all the math" and "dump every research file" are not equivalent instructions. The first creates a public mathematical record. The second can accidentally disclose an applied invention simply because a proof or formula appears somewhere inside its engineering dossier.

This boundary lets the mathematics move aggressively while preserving the option to handle technical inventions deliberately.

Nothing in this file is legal advice or a patentability opinion. It is the operating firewall for this release campaign.
